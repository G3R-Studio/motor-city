# Motor City — roadmap визуального редизайна игровых интерфейсов (HUD-VIS)

Дата начала: 2026-10-12. Статус: **аудит исходников выполнен, реализация визуального редизайна НЕ начата**. Владелец приёмки — пользователь, владелец изменений — ассистент с коммитами в main. Последняя обследованная база: **70b4f058a3a1e0de46d173953891801cbf40b08f**.

> **Область охвата — все запланированные для обновления интерфейсные поверхности**, включая окна и состояния, которых не было на девяти присланных скриншотах. Скриншоты — визуальная отправная точка, НЕ исчерпывающий перечень окон. Красная конструкция над автомобилем на игровом кадре — **часть окружения**, а не «верхний баннер активности». Реальный компонент Activity Status есть в коде, но его нельзя отождествлять с этим фрагментом изображения.
>
> По требованию пользователя: **сначала все игровые и визуальные правки, потом — общая сборка**. Не запускать Unity CI, Source Gates workflow_dispatch, WebGL Release или Pages до отдельного согласования. Ручные Play Mode проверки отдельных изменений и исходниковый анализ возможны. Прошлый успешный релиз относится к другому SHA и не сертифицирует будущий HUD.

## 0. Зачем этот документ и правила продолжения

Цель: сделать запланированные экраны визуально единой системой **clean neon racing UI** — современный, чёткий, не перегруженный гоночный интерфейс. Сохранить узнаваемую фиолетово-синюю тему, машину и город на первом плане, удобство езды на ПК и телефоне, существующие данные и функции.

**Не создавать конкурирующий HUD, отдельные начисления или второй владелец модалки.** Это визуальный/UX рефакторинг поверх работающего геймплея. Точки на миникарте должны оставаться редкими и появляться сразу; зум и маршруты, торможение NPC, дрифт, физику, награды, сохранения и чувствительность тач-контролов не менять без отдельного пользовательского запроса.

**Как вести прогресс**:
1. Пункты имеют постоянный ID: HV-0.1 … HV-10.x и экранные ID FE / PE / DR / MO / GA / TC / FX. ID не переименовывать при правках.
2. Статус этапа: **PLANNED → IN SOURCE → NEEDS UNITY → ACCEPTED**. Отдельно **BLOCKED** с причиной. Чекбокс [x] означает только то, что описано рядом; «исходники готовы» не равно «принято в Unity».
3. За один коммит/небольшую группу коммитов менять **одну подсистему**. После каждого коммита обновлять этот документ: ID, что изменено, SHA, source checks, запрошенный smoke, результат пользователя, оставшиеся ошибки.
4. Если на скриншоте обнаружилась ошибка, починить **этот же блок** до перехода дальше. Не повторять уже принятые правки без регрессии.
5. **Не переходить к HV-10 (сборки)** до завершения визуальной очереди, всех дополнительных пожеланий пользователя и его явного разрешения на сборку.

## 1. Проверенный охват проекта, но не ложная «проверка всех ассетов»

По дереву Git на исходном SHA проиндексированы **4 550 отслеживаемых файлов**, из них **4 287 в Assets**, **260 C#**, **37 C# в Assets/Scripts/UI**; дерево Git не усечено. Это **полный инвентарь путей** репозитория, а не построчное изучение каждого бинарного FBX/PNG, модели или плагина. Реальные builders, UI partials, слой визуального оформления, ресурсы, события ввода и QA-скрипты просмотрены отдельно. До редактирования конкретного экрана читать **полный соответствующий файл** заново на актуальном HEAD. Не утверждать, что все 4 550 файла компилировались или тестировались.

**Фактическая архитектура:**
- **Главное меню и экраны до игры** строятся из C# в Assets/Scripts/UI/MotorCityFrontEndFlow.cs с дополнениями MotorCityFrontEndModalUi.cs и MotorCityFrontEndExperienceSections.cs. При смене RU/EN Canvas пересоздаётся.
- **Внутриигровой HUD** — единый runtime **PrototypeHud**, разбитый на partial-файлы: PrototypeHud.cs создаёт Canvas, safe area и регистрирует строители; внешние экраны и элементы живут в соответствующих *View.cs.
- **Общий стиль** уже частично обеспечивают HudUiFactory.cs, MotorCityModalUiKit.cs, MotorCityButtonVisuals.cs, MotorCityTypography.cs и MotorCityUiThemeAssets.cs. Использовать текущие UI-примитивы и оформление без создания параллельного набора компонентов.
- **Слой HudVisualPolish.cs** после создания HUD стилизует найденные объекты, но по текущему контракту **не должен перехватывать геометрию**, принадлежащую builders. Это важный источник возможных конфликтов.
- **Иконки** выдаёт MotorCityIconLibrary.cs (кэш Resources + fallback); часть символов рисуется векторными элементами. Не допускать третьей разрозненной библиотеки.
- **Визуальные ресурсы:** Assets/Resources/MotorCity/UI/MotorCityUiThemeAssets.asset, Fonts/RobotoCondensed-Regular.ttf и -Bold.ttf, Intro/MainMenu.png, UI/Icons/Kenney, UI/Characters, Art/MotorCity/UI/VilleSeppanen. Проверять существующие лицензии; не тащить Asset Store UI без согласования.
- **UI-текст/языки:** Assets/Scripts/Localization/MotorCityLocalization.cs, MotorCityTextLayout.cs, MotorCityTextClip.cs. Используется Unity UI Text, не предполагать наличие TMP.
- **Input, звук, владение окнами:** Assets/Scripts/Input/MotorCityInput.cs, UI/UiButtonFeedback.cs, Audio/MotorCitySfxRuntime.cs, UI/MotorCityUiEventSystem.cs. Визуальный редизайн не должен порождать повторные onClick/звуки.
- **World-space markers** живут в Assets/Scripts/World/*MarkerVisual.cs и Assets/Scripts/Gameplay/RouteMarkerVisual.cs; это не обычные модальные окна, но входят в визуальную систему навигации.
- **Editor/development UI:** Assets/Scripts/Gameplay/AdminDebugPanel.cs — IMGUI, ограждён UNITY_EDITOR || DEBUG. Отдельная диагностическая поверхность, не переносить в релиз.

## 3. Дизайн-система: предлагаемые токены (к утверждению на первом прототипе)

Значения — **проектные стартовые**, не констатация уже используемых констант. Сверить со снимком в Unity, после чего зафиксировать канонический файл/asset. Единицы размеров — Canvas reference units, не физические пиксели всех устройств.

| Токен | Рекомендация | Применение |
| --- | --- | --- |
| Background/base | #100D20, 90–96% непрозрачности | Непрозрачные карточки и окна поверх яркой сцены |
| Panel/surface | #231A43, 86–94% | Модалки и основные карточки |
| Raised | #30234F, 95% | Hover/selected, разделители важных секций |
| Primary cyan | #54C6FF | Активное действие, выбранный режим, маршрут |
| Secondary lilac | #A68DFF | Бордюры/неосновные действия |
| Text primary | #F3F6FF | Заголовки, числовые значения |
| Text secondary | #B7C4DD | Пояснения, единицы, неподчёркнутые условия |
| Success | #59E99F | Куплено, завершено, подтверждено |
| Warning/gold | #FFCA70 | Награда, элита, неразблокированная возможность |
| Danger | #FF8A79 | Отмена, опасное действие; только когда семантически нужно |
| Outlines | 1–1.5 ед., alpha 0.25–0.45 | Вместо нескольких ярких вложенных рамок |
| Corners | обычно 8–12 ед.; 6 ед. для utility | В существующих UI-примитивах или texture sprites без дорогого shader blur |
| Spacing scale | 4 / 8 / 12 / 16 / 24 / 32 | Единая сетка, внешний отступ 24–32 в панелях |
| Titles | обычно 26–32; secondary 17–21 | Не увеличивать все окна одинаково; RU/EN проверить |
| Body | 15–18; подписи 12–14 | Иерархия, обычный регистр в описаниях |
| Numeric focus | 34–52 для скорости; 20–28 для цен/результатов | Без сжатия hit area соседних кнопок |
| Touch target | минимум около 44–48 reference units + проверка реального touch | Визуальный значок может быть меньше активной площади |

Шрифт: сохранить **Roboto Condensed Regular/Bold**, пока не доказано, что он не подходит. Не вводить новые шрифты исключительно ради декора и не размывать крупный текст тенями. Контраст проверять на светлом городском фоне, при дневном освещении и в сумерках, а не только на тёмном фоне меню.

**Семантика кнопок:** Primary (Продолжить/Выбрать/В город), Secondary (навигация по разделам), Utility (+/−/настройка/циклы), Back/Close (не дублировать два выхода на одном экране без причины), Locked/Disabled (показывать причину, а не «псевдоактивную» покупку). Состояния Normal / Hover / Pressed / Selected / Disabled / Focused оформляются одним способом.

**Эффекты:** допускается лёгкая подсветка выделения и мгновенный press feedback. Новые появления окон — только быстрые 0.10–0.16 c (unscaled time, опционально Reduced Motion/без motion). **Маршрут на миникарте НЕ анимировать и НЕ вводить fade обратно.** Не усиливать звук кнопок и не добавлять резкие высокие ноты: текущий мягкий тихий клик принят пользователем.

## 5. Acceptance contract для каждого визуального изменения

| Область | Что проверяем перед словами «всё чётко» |
| --- | --- |
| Functional | Всё нажимается с прежним результатом, Esc/Back/Continue работают, нет дублированных кнопок/звуков |
| Data | Награды не прибавляются за открытие модалки, locked/unlocked честные, сохранения остаются прежними |
| Layout | Нет обрезаний, наездов, горизонтального скролла в неожиданных местах, пустого огромного пространства |
| Theme | Одна типографика и набор семантик, различимая primary, тонкие рамки, яркие accent только для значимых элементов |
| Responsive | Проверены Desktop, narrow и touch/safe area по применимости; активная область клика не меньше доступной |
| Navigation | Кнопки, фокус, скролл и закрытие; modal ownership единый; нет «зависшей» паузы/блокировки вождения |
| Feedback | Hover/press быстрые, UI tap тихий, маршрут виден мгновенно, анимации не блокируют |
| Evidence | Коммит, фактические изменённые файлы, проведённые source checks, точная область ручной проверки, ответ пользователя |

**Не делать «слепой глобальный replace» цветов или RectTransform в сотнях мест**: сначала общий примитив, затем экран и его владелец, потом user smoke. Не вводить дополнительные Canvas/дублирующие компонентные partial handlers. При подсистеме, которую пользователь не показывал, запросить скриншот **этой** страницы после source-пакета и перед её приёмкой.
