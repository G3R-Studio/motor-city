## 0. Зачем делаем

В Motor City уже существуют гонки, дрифт, доставки, профессии, автомобили, гараж, мастерство, клубы, сюжет, сезон, ежедневные задания, контракты, Турбо (сюжетный навигатор), Пикси (летающий спутник), инспектор Бублик, легенды, ночной клуб, достижения и коллекции. Сейчас игрок часто видит только отдельный HUD-текст и итоговые кредиты, но не понимает:

1. **Что мне сейчас делать?**
2. **Зачем мне это делать?**
3. **Что я получу и что откроется дальше?**

Цель — добавить единый внутриигровой центр **«Мой Motor City»**, каталог активностей, журнал прогресса и подробные результаты активностей. Все данные берутся из текущих игровых систем; никаких дополнительных валют, повторного начисления наград или конкурирующих систем прогресса.

### Границы обновления

**Входит:** понятная навигация по существующим системам, карточки с требованиями и наградами, реальный текущий прогресс, интеграция с существующим навигатором, адаптация к ПК/тач, RU/EN, улучшенное окно результатов.

**Не входит в этот roadmap:** создание новых автомобилей, полиции с реальными погонями, отдельных ИИ-соперников, многопользовательских клубов, настоящего онлайн-рейтинга, каталога платной косметики и новых заработков/валют. Если понадобится, для этих фич открыть отдельные планы.

**Продуктовые правила:**

- Не превращать постоянный HUD в энциклопедию. Основной HUD остаётся компактным: скорость, КР/REP, мини-карта, **одна актуальная цель**, контекстное действие.
- Следовать визуальному стилю Motor City: тёмно-фиолетовые панели, понятная иерархия, крупные сенсорные области, отсутствие дублирующих кнопок.
- Сохранять существующие сохранения и прогресс, не делать reset или выдачу наград при открытии информационных окон.
- Не менять физику машин, FCG-город, traffic, Prometeo controller, порядок bootstrap и существующий runtime.
- Не обещать то, чего ещё нет: клубы пока личные, инспектор не преследует физическими полицейскими машинами, таблицы лидеров и рекламные выплаты зависят от платформы.
- Для заблокированной активности показывать **реальное условие** открытия и понятную причину недоступности; не предлагать запуск в обход сюжетных/обучающих ограничений.

## 1. Архитектура и исходные точки

Это **кандидаты на интеграцию, не разрешение переписать все перечисленные файлы**. Уточнить реальные API и единственного владельца окна в Phase UX-0:

| Область | Что изучить в существующем проекте |
| --- | --- |
| Главное меню / возврат в игру | `Assets/Scripts/UI/MotorCityFrontEndFlow.cs` и его partial UI |
| Основной HUD и модальные окна | `Assets/Scripts/UI/PrototypeHud.cs`, partial view-файлы, UI ownership guard |
| Окно результатов | `Assets/Scripts/UI/ActivityResultView.cs`, точка формирования результата/выдачи награды |
| Маршруты | `Assets/Scripts/UI/NavigatorView.cs`, существующие destination IDs и приоритет текущей активности |
| Гараж | `Assets/Scripts/UI/GarageReferenceLayout.cs` и игровые системы автомобилей |
| Клуб / сюжет / задания | `Assets/Scripts/Gameplay/`: `ClubSystem`, `StoryMissionSystem`, `SeasonSystem`, `DailyAdventureSystem`, `AdventureDirector` и прочие фактические источники |
| Риск, Пикси, мастерство | `CityRiskSystem`, `PixieCompanionSystem`, `VehicleMasterySystem` и связанные системы |
| Локализация | `Assets/Scripts/Localization/MotorCityLocalization.cs` |
| Сохранения | `Assets/Scripts/Persistence/MotorCitySaveService.cs` |
| QA | `Tools/check_ui_layout.ps1`, `Tools/check_phase7_ui_ownership.py`, `Tools/check_phase12_release_profiles.py`, GitHub Actions |

Предпочтительное решение — **тонкий read-only слой для представления** (snapshot/view model), который собирает значения из живых систем и отдаёт их существующему UI. Конкретные классы/методы выбирать **после аудита**, а не создавать абстракции вслепую. Одна точка владеет модальным окном; другие компоненты не меняют её RectTransform.

## 5. Технические запреты и меры безопасности

- **Данные — read-only.** Отображающий код не владеет начислением КР, REP, XP, разблокировкой авто или выдачей клубных наград.
- **Единственный owner макета** на панель; не вводить вторую запись координат через `HudVisualPolish`, если панелью уже владеет view.
- Не читать/переписывать напрямую чужие save keys из UI. Не делать миграцию сохранений ради визуального обновления без отдельного аудита.
- Не размывать разницу между **реализовано в коде**, **показано в интерфейсе**, **проверено в Unity** и **проверено в WebGL браузере**.
- Числа из текущего описания игры (включая КР, REP, таймеры и условия) — **ориентиры для UX**, а не вечные константы. Показывать актуальные значения источников, учитывать баланс и конфигурацию.
- Физические погони, реальные онлайн-клубы, Yandex leaderboard, фото-PNG и расширенный тюнинг **не помечать реализованными** данным UI-проектом.
- На период UX-разработки **GitHub Actions не запускаются автоматически** от push: source checks и Desktop/Mobile WebGL Release доступны только по ручному `workflow_dispatch` (для WebGL нужен явный флаг); GitHub Pages — только вручную с точным `release_run_id`. Режим установлен коммитом [`e0b09e2`](https://github.com/G3R-Studio/motor-city/commit/e0b09e2989a7e169ef15cf7f1a1f7152db0b0ec1). **До UX-7 проверяем только Unity Editor; WebGL не собирать/не публиковать.**
