# Motor City — Player Experience / «Мой Motor City» Roadmap

Создано: **2026-10-11**  
Статус: **UX-0 source audit завершён; UX-1 В РАБОТЕ (2/6 основных чекбоксов; 3 входных/вложенных smoke подтверждены)**. **Последняя поставка:** Пикси на крыше и новые спокойные анимации — исходники обновлены, ручной Unity smoke ещё не проводился. Пользователь проверил в Unity Editor главное меню, возврат из паузы, «Активности» и «Журнал». Автоклуб/Инспектор/Пикси ещё не проверены; WebGL только в UX-7.  
Направление: **сделать существующий игровой прогресс понятным, не переписывая работающие механики**.

> Этот документ — **трекер реализации**, а не описание уже готовых экранов.  
> Отмечать `[x]` только после внесения изменений, успешных проверок и записи проверяемого результата (коммит/Actions/ручной smoke). `[ ]` — не выполнено. Отсутствие багов в source gate не означает, что WebGL проверен в браузере.

## 0. Зачем делаем

В Motor City уже существуют гонки, дрифт, доставки, профессии, автомобили, гараж, мастерство, клубы, сюжет, сезон, ежедневные задания, контракты, Турбо (сюжетный навигатор), Пикси (летающий спутник), инспектор Бублик, легенды, ночной клуб, достижения и коллекции. Сейчас игрок часто видит только отдельный HUD-текст и итоговые кредиты, но не понимает:

1. **Что мне сейчас делать?**
2. **Зачем мне это делать?**
3. **Что я получу и что откроется дальше?**

Цель — добавить единый внутриигровой центр **«Мой Motor City»**, каталог активностей, журнал прогресса и подробные результаты активностей. Все данные берутся из текущих игровых систем; никаких дополнительных валют, повторного начисления наград или конкурирующих систем прогресса.

### Границы обновления

**Входит:** понятная навигация по существующим системам, карточки с требованиями и наградами, реальный текущий прогресс, интеграция с существующим навигатором, адаптация к ПК/тач, RU/EN, улучшенное окно результатов.

**Не входит в этот roadmap:** создание новых автомобилей, полиции с реальными погонями, отдельных ИИ-соперников, многопользовательских клубов, настоящего онлайн-рейтинга, каталога платной косметики и новых заработков/валют. Если понадобится, для этих фич открыть отдельные планы.

**Продуктовые правила:**

- Не превращать постоянный HUD в энциклопедию. Основной HUD остаётся компактным: скорость, КР/REP, мини-карта, **одна актуальная цель**, контекстное действие.
- Следовать визуальному стилю Motor City: тёмно-фиолетовые панели, понятная иерархия, крупные сенсорные области, отсутствие дублирующих кнопок.
- Сохранять существующие сохранения и прогресс, не делать reset или выдачу наград при открытии информационных окон.
- Не менять физику машин, FCG-город, traffic, Prometeo controller, порядок bootstrap и существующий runtime.
- Не обещать то, чего ещё нет: клубы пока личные, инспектор не преследует физическими полицейскими машинами, таблицы лидеров и рекламные выплаты зависят от платформы.
- Для заблокированной активности показывать **реальное условие** открытия и понятную причину недоступности; не предлагать запуск в обход сюжетных/обучающих ограничений.

## 1. Архитектура и исходные точки

Это **кандидаты на интеграцию, не разрешение переписать все перечисленные файлы**. Уточнить реальные API и единственного владельца окна в Phase UX-0:

| Область | Что изучить в существующем проекте |
| --- | --- |
| Главное меню / возврат в игру | `Assets/Scripts/UI/MotorCityFrontEndFlow.cs` и его partial UI |
| Основной HUD и модальные окна | `Assets/Scripts/UI/PrototypeHud.cs`, partial view-файлы, UI ownership guard |
| Окно результатов | `Assets/Scripts/UI/ActivityResultView.cs`, точка формирования результата/выдачи награды |
| Маршруты | `Assets/Scripts/UI/NavigatorView.cs`, существующие destination IDs и приоритет текущей активности |
| Гараж | `Assets/Scripts/UI/GarageReferenceLayout.cs` и игровые системы автомобилей |
| Клуб / сюжет / задания | `Assets/Scripts/Gameplay/`: `ClubSystem`, `StoryMissionSystem`, `SeasonSystem`, `DailyAdventureSystem`, `AdventureDirector` и прочие фактические источники |
| Риск, Пикси, мастерство | `CityRiskSystem`, `PixieCompanionSystem`, `VehicleMasterySystem` и связанные системы |
| Локализация | `Assets/Scripts/Localization/MotorCityLocalization.cs` |
| Сохранения | `Assets/Scripts/Persistence/MotorCitySaveService.cs` |
| QA | `Tools/check_ui_layout.ps1`, `Tools/check_phase7_ui_ownership.py`, `Tools/check_phase12_release_profiles.py`, GitHub Actions |

Предпочтительное решение — **тонкий read-only слой для представления** (snapshot/view model), который собирает значения из живых систем и отдаёт их существующему UI. Конкретные классы/методы выбирать **после аудита**, а не создавать абстракции вслепую. Одна точка владеет модальным окном; другие компоненты не меняют её RectTransform.

### UX-2 — Полноценный каталог активностей (первая пользовательская ценность)

- [ ] Для каждой карточки: «что это», «как начать», «что требуется», **текущие рекорды/медали**, актуальные награды, состояние блокировки и следующий рубеж.
- [ ] Показывать реальные ограничения (уровень дисциплины для Elite/Premium, требования сюжетной активности, ночные условия) с объяснением без спойлеров.
- [ ] Кнопка **«ПОСТРОИТЬ МАРШРУТ»** переиспользует доступные `NavigatorView` destinations. Нет соответствующего маршрута — не рисовать ложный маркер; показать понятное состояние.

**Готово, когда:** игрок из каталога понимает, как начать каждую существующую активность, видит правдивые награды/условия и может перейти к поддерживаемому маршруту без поломки активного задания.

### UX-4 — Подробные страницы существующих систем

- [ ] **Автоклуб:** выбранный клуб, специализация, что засчитывается, личный вклад `x/y`, цель/награда недели, состояние получения награды. Не изображать общий онлайн-прогресс участников.
- [ ] **Инспектор Бублик:** текущий уровень внимания и значение/диапазон (если доступно), причины роста, способы снизить, состояние наблюдения. **Не** обещать погоню/штрафы, которых нет.
- [ ] **Пикси:** уровень, XP/следующий порог, реально открытые способности, ежедневная задача и текущий прогресс. **Турбо** — отдельный NPC/помощник в навигаторе, XP/скинов спутника не имеет. [Канон персонажей](CharacterCanon-Turbo-Pixie.md).
- [ ] **Мой гараж:** открытые/заблокированные автомобили, необходимая REP, индивидуальное мастерство, специализация, ближайшее улучшение, история. Не создавать альтернативный экран покупки.
- [ ] **Достижения и коллекции:** получено/доступно, рекорды, условия и одноразовые награды; сохранять существующий секретный контент закрытым, пока он действительно не разблокирован.
- [ ] **Ночной клуб и легенды:** требования доверия/дисциплины/мастерства, текущие этапы, способы прогрессировать; чётко обозначить, что легенды — игровые цели, а не физические ИИ-дуэли.

**Готово, когда:** игрок понимает каждую вторичную систему, а новые экраны не создают ложных обещаний и не меняют её баланс.

### UX-5 — Новое окно результата активности

- [ ] Сохранить **основные итоги**: название, медаль/результат, кредиты, REP, кнопки **«В ГОРОД»** и **«ПОВТОРИТЬ»** (последние — по действующим условиям).
- [ ] Ниже компактно отображать **фактически изменившиеся** вторичные системы: мастерство машины, дисциплина, клуб, дневные/сюжетные/сезонные задачи, контракты, рекорды, Пикси, инспектор и прочее, **только если данные действительно поменялись**.
- [ ] Зафиксировать атомарный **before/after snapshot** или иное надёжное событие результатов; не вычислять «награду» по теоретическим формулам, если сервер/баланс/бонусы дали другое значение.
- [ ] Обработка случаев: провал, повтор без новой медали, неактивный клуб, достигнутый максимум, сюжетная блокировка, отключённый платформенный сервис, серия быстро следующих событий.
- [ ] Исключить двойную выплату/двойную запись при повторном открытии окна, reload, `Continue`, Retry и отмене.
- [ ] Уместить в Desktop/Mobile: при большом количестве наград — сворачиваемый раздел или прокрутка, без навязчивых всплывающих уведомлений.

**Готово, когда:** завершение активности объясняет **что изменилось**, повторный просмотр ничего не начисляет, а старый игровой цикл Retry/Continue сохранён.

## 4. Сценарии приёмки (обязательная матрица)

| Сценарий | Ожидаемый результат |
| --- | --- |
| Новый игрок до конца обучения | Не получает преждевременно недоступные активности; понятный следующий шаг |
| Игрок после обучения | Видит одну актуальную цель и доступные направления |
| Активный спринт/доставка | Каталог не перезаписывает чекпоинты активного задания |
| Один успешный спринт | Фактические КР/REP и изменившиеся вторичные прогрессы без двойной награды |
| Повтор без улучшения медали/рекорда | Интерфейс честно показывает отсутствие новой одноразовой награды |
| Смена машины | Карточки мастерства/специализации переключаются, индивидуальный прогресс сохраняется |
| Ежедневная/недельная ротация | Правильные новые задачи и отсутствие повторного получения старой награды |
| Выход через паузу в главное меню и `Continue` | Корректная повторная схема выбора управления и состояние модалок |
| Браузерная перезагрузка с существующим save | Тот же прогресс, состояние меню не ломает игру |
| WebGL GitHub Pages без Yandex SDK | Платформенные действия остаются корректно недоступными, UI не зависает |
| Реальный тач/узкий экран | Ничего не перекрывает газ/руль/стрелки; кнопки закрытия доступны |
| RU/EN | Нет пустых локализаций и обрезанных важных требований |

## 5. Технические запреты и меры безопасности

- **Данные — read-only.** Отображающий код не владеет начислением КР, REP, XP, разблокировкой авто или выдачей клубных наград.
- **Единственный owner макета** на панель; не вводить вторую запись координат через `HudVisualPolish`, если панелью уже владеет view.
- Не читать/переписывать напрямую чужие save keys из UI. Не делать миграцию сохранений ради визуального обновления без отдельного аудита.
- Не размывать разницу между **реализовано в коде**, **показано в интерфейсе**, **проверено в Unity** и **проверено в WebGL браузере**.
- Числа из текущего описания игры (включая КР, REP, таймеры и условия) — **ориентиры для UX**, а не вечные константы. Показывать актуальные значения источников, учитывать баланс и конфигурацию.
- Физические погони, реальные онлайн-клубы, Yandex leaderboard, фото-PNG и расширенный тюнинг **не помечать реализованными** данным UI-проектом.
- На период UX-разработки **GitHub Actions не запускаются автоматически** от push: source checks и Desktop/Mobile WebGL Release доступны только по ручному `workflow_dispatch` (для WebGL нужен явный флаг); GitHub Pages — только вручную с точным `release_run_id`. Режим установлен коммитом [`e0b09e2`](https://github.com/G3R-Studio/motor-city/commit/e0b09e2989a7e169ef15cf7f1a1f7152db0b0ec1). **До UX-7 проверяем только Unity Editor; WebGL не собирать/не публиковать.**
